# Подключение входа через GitHub и Яндекс в Recall

Обновление добавляет два OAuth-провайдера. Существующие пользователи, пароли, заметки, теги и связи не меняются. Новые OAuth-идентичности привязываются к уже существующему аккаунту из раздела «Безопасность»; автоматического объединения аккаунтов по совпадающему email нет.

## 1. Установить обновление

1. Сделать резервную копию базы PostgreSQL.
2. Остановить Uvicorn (`Ctrl+C`).
3. Распаковать архив обновления в корень `C:\Users\machenike\recall`, сохраняя структуру папок.
4. В активированном `.venv` выполнить:

   ```powershell
   python run_sql_migrations.py
   ```

5. После успешной миграции запустить приложение:

   ```powershell
   uvicorn app.main:app --reload --port 8080
   ```

Миграция `007_oauth_accounts.sql` создаёт только таблицу внешних идентификаторов и функции для их безопасного связывания. Данные заметок не меняются.

## 2. Зарегистрировать OAuth-приложение GitHub

1. Открыть GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.
2. Application name: `Recall`.
3. Homepage URL: значение `RECALL_PUBLIC_BASE_URL` из `.env`.
4. Authorization callback URL:

   `https://ВАШ-ПУБЛИЧНЫЙ-АДРЕС/auth/oauth/github/callback`

5. Сохранить приложение, скопировать Client ID и сгенерировать Client Secret.

Recall запрашивает только `read:user` и `user:email`. Репозитории и содержимое GitHub не запрашиваются.

## 3. Зарегистрировать приложение Яндекс ID

1. Открыть панель разработчика Яндекс OAuth: https://oauth.yandex.ru/.
2. Создать приложение типа «Для авторизации на стороннем сервисе» / «Для входа пользователей».
3. В правах API Яндекс ID разрешить информацию о пользователе и адрес электронной почты (`login:info`, `login:email`).
4. Добавить callback/Redirect URI:

   `https://ВАШ-ПУБЛИЧНЫЙ-АДРЕС/auth/oauth/yandex/callback`

5. Сохранить приложение и скопировать Client ID и Client Secret.

## 4. Добавить ключи в `.env`

Добавить в самый низ существующего `.env` (не удаляя параметры базы и SMTP):

```env
RECALL_GITHUB_CLIENT_ID=значение_client_id_github
RECALL_GITHUB_CLIENT_SECRET=значение_client_secret_github
RECALL_YANDEX_CLIENT_ID=значение_client_id_yandex
RECALL_YANDEX_CLIENT_SECRET=значение_client_secret_yandex
```

Не присылать `.env`, Client Secret и пароли в чат. После изменения `.env` перезапустить Uvicorn.

## 5. Подключить провайдеры к существующему аккаунту

1. Войти в Recall привычным способом — по текущему логину/email и паролю.
2. Открыть «Безопасность».
3. Нажать «Подключить» рядом с GitHub, пройти авторизацию и вернуться в Recall.
4. Повторить для Яндекса.
5. Проверить, что оба провайдера отображаются как подключённые.

Это привяжет OAuth-идентичности именно к текущему аккаунту Recall, независимо от того, какой email используется в GitHub или Яндексе. Затем можно выйти и проверить каждую кнопку на странице входа.

Если OAuth-идентичность ещё не привязана, вход через неё не создаёт новый аккаунт автоматически. Нужно войти старым способом и подключить провайдера в «Безопасности». Это предотвращает случайное создание второго аккаунта.

## Важно про Cloudflare Quick Tunnel

OAuth-провайдеры проверяют точный callback URL. Если временный адрес `trycloudflare.com` поменяется, нужно обновить `RECALL_PUBLIC_BASE_URL` и callback URL в настройках обоих OAuth-приложений. Для постоянного использования стоит перейти на постоянный домен или именованный Cloudflare Tunnel.

## Безопасность

- OAuth Authorization Code Flow использует `state` и PKCE S256.
- В Recall хранится только ID пользователя у провайдера и минимум метаданных; OAuth access token не сохраняется.
- Email из OAuth-профиля не используется для автоматического объединения аккаунтов.
- OAuth-идентичность можно связать только с текущим подтверждённым входом Recall.
- GitHub запрашивает email scope, но не доступ к репозиториям.
